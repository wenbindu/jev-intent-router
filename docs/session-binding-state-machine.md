# Session 与持久任务

本文描述当前实现。状态机只记录一个持久任务，设备属性单独管理。

## 数据归属

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| `messages` | 浏览器主消息列表 | 所有对话 Agent 共享历史；工具调用与结果也在同一列表 |
| `task_state.current_task` | 上轮返回值，初始 `agent_chat` | 当前持久任务，可以是 Agent、持久工具或 `null` |
| `device_state` | 从主消息列表中的成功工具结果重建 | 音量、静音等设备属性；成功结果中的同名字段增量合并 |
| `persistent_task` | `tools.yaml` | 决定成功执行后是否接管持久任务 |
| `_route` | 消息展示元数据 | 记录处理路径，发送给模型前过滤 |

浏览器只提交 `messages` 和 `task_state`。设备状态不作为独立的客户端输入，避免两份状态互相矛盾。旧音量结果由 `device.py` 统一兼容。

## 每轮处理

```text
输入 + 主消息列表 + 当前任务
  → Jev 单次 choice
  → confidence > 对应阈值？
      是：调用选中的 Agent / Tool
      否：当前任务为 Agent 则继续它，否则调用闲聊 Agent 澄清
  → 返回工具结果、文本、耗时和最终状态
```

Jev 接收完整历史的文本视图、当前任务及设备属性。六个对话 Agent 共享全部对话；工具提参使用相关工具的完整历史轮次及本轮任务背景。历史不使用额外 LLM 摘要。

## 状态转移

| 事件 | 当前任务 |
| --- | --- |
| Agent 成功回答且不是阈值回退 | 若 `persistent_task=true`，替换为该 Agent |
| 持久工具成功执行 | 立即替换为该工具 |
| 瞬时工具成功执行 | 保持原任务 |
| 工具失败 | 保持原任务及设备属性 |
| 工具成功，但最终回答失败 | 保留已经执行成功的状态 |
| 歌曲停止成功 | 仅当当前任务是 `tool_song_play` 时清空任务 |
| 告别成功 | 清空任务；下轮开始新会话 |
| 低置信度回退 | 保持原任务，不自动重放持久工具 |

播放器的 `playing / paused / stopped` 是歌曲工具内部的执行状态，从最近成功的歌曲结果读取，不扩展主状态机。失败操作不能覆盖先前成功状态。

## API 与事件

`POST /api/turn` 返回 NDJSON，一行一个事件：

- `status`：阶段说明。
- `route`：建议路由、实际路由、阈值、置信度与执行器信息。
- `timing`：阶段耗时与 token 用量。
- `tool`：实际工具调用和结果，同时返回已提交的状态。
- `delta`：增量文本。
- `done`：最终回答、任务及设备状态。
- `error`：错误及当前已提交状态。

取消流会取消后台任务。已发出的工具结果可能已经生效，不能根据最终回答是否完成来回滚。

## 边界与后续工作

- Session 仅在浏览器内存中；刷新、清空或新会话会重置。没有服务端会话存储或活动栈。
- 当前状态帮助模型理解背景，但不保证消除歧义。健身中的“换一个”仍可能被 Jev 误判为歌曲控制；阈值也不是跨场景授权校验。
- 工具参数调用仍为 `tool_choice=required`。需要针对当前任务、近邻对话及明确跨场景请求建立真实模型评测后，再考虑允许工具拒绝或澄清；不要靠堆叠个例关键词修补。
- 当前所有设备动作均为模拟。接入真实设备前，需要明确命令授权、幂等和失败确认协议。
